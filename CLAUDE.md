# Italingua

Личное iOS/macOS-приложение для изучения итальянского по уровням, по структуре курса
Т. Буэно, Д. Шевляковой «Базовый курс итальянского языка» (АСТ). Только для личного
использования, никогда не публикуется, репозиторий приватный.

## Стек
- Swift, SwiftUI, SwiftData, iOS 26 / macOS 26.
- Apple Foundation Models framework (on-device LLM).
- Полностью офлайн: без сети и без сторонних API.
- Инструменты извлечения контента — Python в `tools/` (venv в `tools/.venv`, в git не попадает).

## Роль Foundation Models
- Генерирует упражнения, проверяет свободные ответы, адаптирует тексты под уровень.
- Учебный контент (уроки, грамматика, лексика) НЕ генерируется моделью — он статичный и проверенный, лежит в `Content/*.json`.
- Знания об API Foundation Models могут быть устаревшими: перед написанием кода с FM
  сверяться с актуальной документацией (developer.apple.com/documentation/foundationmodels).

## Правила
- PDF учебника лежит в `source/` — папка в `.gitignore`, книга никогда не попадает в git.
- Из книги извлекается ТОЛЬКО структура: названия уроков, грамматические темы, лексика,
  речевые шаблоны. Не копировать дословно объяснения, диалоги, тексты и упражнения.
- Поле `rule_ru`: тексты правил написаны с нуля (по просьбе владельца), не из книги; владелец их правит.
  Новые правила тоже писать своими словами, объяснения из книги не копировать.
  Правила живут в `tools/curation/<LEVEL>.json` (`lessons.<id>.rules`). Их можно писать в приложении
  (экран темы → «Изменить», синхронизируется через iCloud), затем «Экспорт правил» →
  `python3 tools/import_rules.py <файл>` → перегенерация JSON → пересборка.
- Небольшие осмысленные коммиты.
- Перед крупными архитектурными решениями — спрашивать владельца.

## Структура
- `source/` — PDF (игнорируется git).
- `tools/` — скрипты извлечения и валидации.
- `Content/<LEVEL>.json` — контент по уровням (`A1.json`, …).

## Извлечение контента
```bash
python3 -m venv tools/.venv && tools/.venv/bin/pip install -r tools/requirements.txt
tools/.venv/bin/python tools/extract_structure.py --level A1   # -> Content/A1.json
python3 tools/validate_content.py --warnings                   # без зависимостей
```
- Уровни: A1 = вводный курс 1–5 + основной 1–15; A2 = основной 16–35.
- Названия уроков, шаблоны и ручные правки лексики — `tools/curation/<LEVEL>.json`.
- Генерированный `Content/*.json` руками не правим: правки идут в curation и перегенерацию.

## Приложение
```bash
xcodegen generate            # Italingua.xcodeproj генерируется из project.yml, в git не лежит
xcodebuild -project Italingua.xcodeproj -scheme Italingua -destination 'platform=macOS' \
  -derivedDataPath build CODE_SIGNING_ALLOWED=NO test
```
- Один мультиплатформенный таргет (iOS + macOS 26), настройки подписи — `Config/Base.xcconfig`.
- SwiftData: хранилище `Content` (локальное, пересоздаётся из JSON при смене хеша) и
  `Progress` (CloudKit, `.automatic`). Прогресс ссылается на слова по `wordID` = `<level>/<слово без диакритики>`.
- Модели прогресса совместимы с CloudKit: без `unique`, у всех полей значения по умолчанию.
- FM: промпты на английском — русский язык моделью не поддерживается (проверено: `supportsLocale(ru_RU) == false`).
  Ответ упражнения всегда берётся из статичного контента, модель пишет только контекст.
  Стандартные guardrails отклоняли ~50% обычных слов (madre, caffè, due) — генерация идёт текстом через
  `SystemLanguageModel(guardrails: .permissiveContentTransformations)`, с примерами в инструкции и
  второй проверкой грамматики моделью (`SentenceReview`). Модель ошибается и после проверки — это пример, не эталон.
- Свободные ответы («Переведи фразу», `TranslationChecker`): фразы — `ex:` из правил урока. Совпадение с образцом и
  ударения проверяет код; модель только предлагает минимальное исправление (`SentenceFix`), разницу и тип ошибки
  считает код. Прямой вердикт модели был ненадёжен (замерено), поэтому его не спрашиваем; есть «Мой вариант тоже верен».
- Чтение (`ReadingGenerator`): модель пишет текст на словах урока или упрощает вставленный текст до A1/A2;
  словарик под текстом — из статичного контента.

## Разметка правил (`rule_ru`)
```
Абзац с **жирным**.
• пункт списка
! «осторожно» — подряд идущие строки образуют одну карточку
ex: Abito a Mosca. | Я живу в Москве.        ← пример с озвучкой
conj: parlare | говорить                      ← таблица спряжения: 6 строк,
io parl|o                                       «|» отделяет окончание,
...                                             пустая строка завершает таблицу
table: Буква | Название* | Звук               ← таблица: шапка, «*» — колонка с озвучкой,
A a | a | [а]                                   строки той же ширины до пустой строки
```
Валидатор проверяет разметку.
Ответ голосом в «Вставь слово» — `SpeechAnalyzer`/`SpeechTranscriber` (it-IT, на устройстве, пакет языка
скачивается один раз); проверяется распознанное слово, не акцент. Настройки (тема, голосовые ответы) —
`App/Settings`, хранятся в `@AppStorage`. Озвучка — системный TTS (`AVSpeechSynthesizer`, it-IT), офлайн.
Дизайн — вариант B «Карточки» (`App/Views/Theme.swift`).

## Языки интерфейса
- Интерфейс: ru (исходный), en, es — `App/Localizable.xcstrings`, `App/InfoPlist.xcstrings`. Строки в коде — русские
  литералы через `String(localized:)`; новые строки добавлять в каталог с переводами en/es.
- Выбор языка: Настройки → «Язык интерфейса» (`AppLanguage`), через `AppleLanguages`, применяется после перезапуска
  (так переводятся и системные меню macOS).
- Учебный контент: поля `en`/`es` у слов и `topic_en`/`rule_en`/`topic_es`/`rule_es` у тем; пусто — показывается
  русский (`AppLanguage.pick`). Правила правятся в приложении только на русском.
- Переводы тем и правил на en/es написаны вручную: `tools/curation/<LEVEL>.translations.json`; при изменении русского
  правила обновлять и их (валидатор проверяет разметку и предупреждает о непереведённых).
- Переводы слов на en/es делает модель на устройстве (решение владельца): `tools/translate/translate_words.swift` →
  `tools/curation/<LEVEL>.words.json` (дозаписывает только новые слова; ошибки правятся прямо в этом файле).
